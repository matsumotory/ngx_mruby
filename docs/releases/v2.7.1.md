# ngx_mruby v2.7.1

## Behavior changes: read before upgrading

### A body filter that calls Nginx.rputs after an mruby header filter no longer logs "header already sent" or sets the status to 200 (#563)

- Before: in a location with an mruby header filter and an mruby body filter whose code calls `Nginx.rputs` or `Nginx.echo` (which the docs say is not supported there), nginx logged `[alert] header already sent` for every request, and the body filter set the status to 200 after the header was sent. The client received the status that nginx sent, but the log phase saw 200: a log handler and `$status` in `log_format` read 200 for a 404 response.
- Now: nginx does not log that alert, and the log phase sees the status that nginx sent. The response is the same as before.
- Affected: locations with `mruby_output_header_filter` (or `_code`) and `mruby_output_body_filter` (or `_code`) whose body filter calls `Nginx.rputs` or `Nginx.echo`; access logs, log handlers and alerts that read `$status` or the `header already sent` line for those requests.
- What to do: nothing, unless a log statistic or an alert counts on the status 200 or on the `header already sent` line of those requests. The output of `Nginx.rputs` in a body filter is still dropped, as before.

## New features

None.

## Fixes

- A location with an mruby handler that writes the response with `Nginx.rputs` or `Nginx.echo`, such as a content or rewrite handler, and an mruby header filter no longer crashes the worker; the header filter runs once (#563, fixes #206).
- A header filter that calls `Nginx.rputs` or `Nginx.echo` no longer crashes the worker, but the call is still not supported: `Content-Length` counts the output, the body does not contain it, and a log handler, if the location has one, sends it after the response (#563).

## Build and test changes

- The test suite also listens on port 18138, for `test/conf/conf.d/54-output-filters-with-content-handler.conf` (#563).

## Upgrading

- Supported nginx versions: the mainline and stable lines (README.md). CI builds 1.26.3, 1.28.3, 1.30.5 and 1.31.6.
- Rebuilding ngx_mruby with nginx, as `docs/install/` describes, is enough for the changes recorded above.
- What to do: nothing, unless a log statistic or an alert counts on the status 200 or on the `header already sent` line of requests whose body filter calls `Nginx.rputs` after an mruby header filter (#563).
