# ngx_mruby v2.7.1

## Behavior changes: read before upgrading

### A content handler that ends without output answers 500 instead of sending no response (#566)

- Before: a content handler on the main request that ended without output and either set no status (it wrote nothing, or only `""` or `nil` with `Nginx.rputs`, or only set response headers) or set a status below 300 other than 200, 201 and 204 (for example `Nginx::HTTP_ACCEPTED`), also after `Nginx::Async::HTTP.sub_request` resumed it, sent no response. nginx closed an HTTP/1.0 connection without sending a byte and kept an HTTP/1.1 keep-alive connection open without a response until `keepalive_timeout` (75 s by default), so the client waited for its own timeout.
- Now: such a request gets 500 with nginx's error page (or the `error_page` configured for 500) and `Connection: close`, the answer that `Nginx.return Nginx::HTTP_OK` without output already gets. error.log gets a line at the `error` level: `status code is not set, and response body is empty. return NGX_HTTP_INTERNAL_SERVER_ERROR`, or `status code is <N>, but response body is empty. return NGX_HTTP_INTERNAL_SERVER_ERROR`.
- Affected: `mruby_content_handler` and `mruby_content_handler_code` handlers that can end without output, for example a handler that writes only when a condition holds, or one that passes a value that can be empty or `nil` to `Nginx.rputs`. Unchanged: `Nginx::HTTP_OK` without output (500, as before), 201, 204 and the statuses from 300 up (nginx answers them), handlers with output, `Nginx.redirect`, the other handlers, and subrequests (`Nginx::Async::HTTP.sub_request`, SSI includes and `auth_request` see the same subrequest status as before).
- What to do: a handler that should answer with an empty body returns `Nginx.return Nginx::HTTP_NO_CONTENT` (nginx answers 204 itself) or writes a body; a handler that means to deny returns the status it means (`Nginx::HTTP_FORBIDDEN`, `Nginx::HTTP_UNAUTHORIZED`). Log monitoring that matches `status code is 200, but response body is empty` should match `response body is empty. return NGX_HTTP_INTERNAL_SERVER_ERROR` to see the new lines too. Why the behavior changes: a request without a response is a defect (#225); the client hangs until a timeout and a keep-alive connection is held for nothing.
- Not changed by this release: a content handler that writes output and then sets a status below 300 other than 200, 201 and 204, for example `Nginx.rputs "x"` followed by `Nginx.return Nginx::HTTP_ACCEPTED`, still sends no response, as described under "Before".

## Upgrading

Supported nginx versions: the nginx mainline and stable lines (see
[README.md](../../README.md)). Rebuild the module with this release. Check
these before upgrading:

- A content handler that can end without output: return `Nginx::HTTP_NO_CONTENT` or write a body, and update log monitoring that matches `status code is 200, but response body is empty` (#566).
