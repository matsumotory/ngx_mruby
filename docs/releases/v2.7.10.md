# ngx_mruby v2.7.10

## Behavior changes: read before upgrading

None.

## New features

None.

## Fixes

- An SSI page that includes, after another include, a location with an mruby body filter whose body was written with `Nginx.rputs` or `Nginx.echo` (by its content handler, or by a rewrite handler before the request went on to the content) gets its whole response. Before, the client got at most the part of the page before that include, and nginx closed the connection after `send_timeout`. nginx keeps the output of such an include until the includes before it are sent, and then calls its filters again with no new data to send it; the body filter took these calls for the start of a new body and held them back (#827)

## Build and test changes

- `test/t/cases/ssi_body_filter.rb` requests three more SSI pages of `test/conf/conf.d/91-ssi-body-filter.conf` (port 18146), each of which includes a static file and then a location whose body comes from `Nginx.rputs` and goes through a body filter: a content handler, the same with a header filter, and a static file after a rewrite handler that writes with `Nginx.rputs` and declines (#827)

## Upgrading

- No directive was added, renamed or removed. Rebuild the module with this
  release the way you built 2.7.9, and replace the binary or the dynamic
  module as usual. `Nginx.module_version` returns `2.7.10`.

Nothing else needs to be checked before upgrading: this release has no
behavior change.
