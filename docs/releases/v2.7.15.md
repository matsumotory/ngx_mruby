# ngx_mruby v2.7.15

## Behavior changes: read before upgrading

### An mruby body filter no longer runs a second time on the empty buffer at the end of a proxied response

- Before: on a response from an upstream (`proxy_pass`, `fastcgi_pass`, `uwsgi_pass`, `scgi_pass` or `memcached_pass`), after an earlier phase handler left `Nginx.rputs` or `Nginx.echo` output in the module context and then declined, an `mruby_output_body_filter(_code)` ran a second time on the empty last buffer that the upstream sends after the body. A body filter whose output on an empty body is non-empty, such as one that prepends to or appends to `f.body`, produced bytes on that second run, and they were sent after the response, past its `Content-Length`.
- Now: the body filter passes that trailing empty buffer on without running its code again, so no bytes are sent after the framed response.
- Why it changed:
  - The defect: the bytes that a body filter whose output on an empty body is non-empty produced on the second run and that were sent past the response's `Content-Length`.
  - Why the old behavior could not be kept: the second run had no body to transform, so any bytes it produced could only follow a response that was already framed and sent.
  - What the documentation promised: `docs/class_and_method/` did not describe the body filter running a second time, and `docs/directives/` did not describe output after the response.
- Affected: a location with `mruby_output_body_filter(_code)` whose output on an empty body is non-empty, served from an upstream whose `Content-Length` is known, with an earlier handler that leaves `Nginx.rputs` or `Nginx.echo` output and then returns a negative code the request declines past (in practice `Nginx::DECLINED`). A body filter that leaves an empty body empty, such as `f.body = f.body.upcase`, a static file, and a response sent chunked are unchanged.
- What to do: nothing; rebuild the module with this release. A body filter that was guarded against an empty body (for example with `unless f.body.empty?`) can keep the guard or drop it.

## New features

None.

## Fixes

- The build links with GNU make 3.81, the make that macOS ships as `/usr/bin/make`. mruby's `libmruby.flags.mak` sets `MRUBY_PACKAGE_DIR` with `!=`, which GNU make 4.0 added, so make 3.81 left it empty and the link of nginx looked for `/lib/libmruby.a`. `Makefile.in` now sets the variable when it is empty; builds with GNU make 4.0 and later are unchanged (#872)

## Build and test changes

None.

## Upgrading

- No directive was added, renamed or removed. Rebuild the module with this release the way you built 2.7.14, and replace the binary or the dynamic module as usual. `Nginx.module_version` returns `2.7.15`.

Read "Behavior changes: read before upgrading" above before you upgrade.
