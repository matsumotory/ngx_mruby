# ngx_mruby v2.7.11

## Behavior changes: read before upgrading

- Deleting a request or response header whose name is a prefix of another
  header no longer deletes the longer header. Before, `r.headers_in.delete("X-Foo")`
  also removed a header named `X-Foo-Bar`, because the delete compared only the
  first bytes of the name. Now it removes only a header named exactly `X-Foo`.
  This affects a configuration that deleted a header by a name that is a prefix
  of another header and relied on both being removed; delete each header by its
  exact name.

## New features

None.

## Fixes

- `Nginx::Var`'s setter and `Nginx::Var#set` now assign a variable that has a
  set_handler, such as `$args` or `$limit_rate`. Before, they passed a value
  struct whose fields were not set to the set_handler, so the assigned value did
  not take effect, and using the variable afterwards could end the worker
  process. The value struct is now filled before the set_handler runs, as nginx
  does
- Deleting a request or response header from the middle of a full header list
  part no longer writes past the end of the part's array when headers are added
  afterwards, and a header added right after the first part of the list empties
  is kept. The delete now removes the element by moving the rest of the part
  down, keeping the list's last-part pointer in step

## Build and test changes

- `test/t/cases/var_setter_init.rb` (with `test/conf/conf.d/72-var-setter-init.conf`,
  port 18104, and `test/html/var_setter_init.rb`) assigns `$args` through the
  setter of `Nginx::Var` and through `Nginx::Var#set` and reads it back
- `test/t/cases/header_del.rb` (with `test/conf/conf.d/73-header-del.conf`, port
  18105, and `test/html/header_del.rb`) deletes a request header: a name that is
  a prefix of a header, emptying the full first part while a second part exists,
  and deleting from the middle of a full part before adding headers

## Upgrading

- No directive was added, renamed or removed. Rebuild the module with this
  release the way you built 2.7.10, and replace the binary or the dynamic
  module as usual. `Nginx.module_version` returns `2.7.11`.

Read "Behavior changes: read before upgrading" above before upgrading.
