# ngx_mruby v2.7.11

## 更新前に確認する挙動の変更

### 1. Nginx::Varが、$argsや$limit_rateのようにset_handlerを持つ変数に値を正しく代入する

`Nginx::Var`でset_handlerを持つ変数に代入する件のアドバイザリ：[GHSA-r7v5-479r-hmqr](https://github.com/matsumotory/ngx_mruby/security/advisories/GHSA-r7v5-479r-hmqr)

- 変更前：`Nginx::Var`のアクセサ(`v.name = value`)と`Nginx::Var#set(name, value)`は、set_handlerを持つnginxの変数に代入するとき、値の構造体(`ngx_http_variable_value_t`)を`ngx_palloc`で確保し、そのフィールドを埋める前にset_handlerを呼んでいました。set_handlerを持つ変数とは、変更できる変数のうち、代入をnginxがハンドラで処理するもので、`$args`や`$limit_rate`がその例です。set_handlerは、未初期化の構造体から`len`と`data`を読みます。`$limit_rate`は未初期化のサイズを解釈し、`$args`は未初期化の長さとポインタを`r->args`にコピーしていました。そのため、代入した値は反映されませんでした。また、その後に変数を使うと、ワーカーの未初期化のメモリを読みました。値を読み戻すときや、`$args`をクライアントへ送るときがこれにあたります。その結果、ワーカープロセスが終了するか、ワーカーのメモリが外へ送られることがありました。
- 変更後：ngx_mrubyは、set_handlerを呼ぶ前に、値の構造体のフラグ、`data`、`len`を埋めるようになりました。nginxがこのような変数に代入するときと同じ順序です。アクセサ(`ngx_mrb_var_set_vector`)と`Nginx::Var#set`(`ngx_mrb_var_set_func`)の両方を変更したので、set_handlerを持つすべての変数で、代入した値が反映されます。
- 変更の理由：
  - 不具合：set_handlerに渡す値の構造体は、`ngx_palloc`で確保したままで、フィールドが設定されていませんでした。そのため、set_handlerは未初期化の長さとポインタを読みました。
  - 前の挙動を残せなかった理由：代入した値が変数に届きませんでした。また、未初期化のメモリを読むことは、メモリ安全性の問題です。ワーカーはメモリを使い回すので、そのメモリに以前のデータの断片やヒープのポインタが残っていることがあり、それが`$args`を通じてクライアントへ送られることがあります。
  - ドキュメントが示していた挙動：アクセサの[`Nginx::Var#method_missing`](../class_and_method/README.md#nginxvarmethod_missingsymbol--args---result)と[`Nginx::Var#set`](../class_and_method/README.md#nginxvarsetname-value)は、nginxの変数に値を設定すると書いています。set_handlerを持つ変数に代入すると、変数が設定されないままになることや、関係の無いメモリを読むことについては、ドキュメントに書かれていません。
- 影響の範囲：mrubyのコードで、`$args`、`$limit_rate`などset_handlerを持つ変数に`Nginx::Var`のアクセサか`#set`で代入し、その後にその変数を使う設定です。
- 必要な対応：対応は不要です。代入した値は反映されます。以前のリリースのまま更新できない場合は、これらの変数の値は、`Nginx::Var`ではなくnginxの設定ファイルで指定してください。
- テスト：`test/t/cases/var_setter_init.rb`のポート18104のテストです。

### 2. リクエストかレスポンスのヘッダの削除が、ヘッダのリストの外に書き込まず、名前が完全に一致するヘッダだけを削除し、後で追加したヘッダを残す

リクエストかレスポンスのヘッダの削除の件のアドバイザリ：[GHSA-2gcp-h74q-c9g6](https://github.com/matsumotory/ngx_mruby/security/advisories/GHSA-2gcp-h74q-c9g6)

- 変更前：`ngx_mrb_del_request_header`は、ヘッダのngx_listを順に調べ、満杯のpartの途中で名前が一致すると、そのpartを分割していました。この関数は、`Nginx::Headers_in#delete`と`Nginx::Headers_out#delete`から呼ばれます。`[]=`も、ヘッダを更新するとき、追加の前の削除にこの関数を呼びます。分割では、元のpartの配列の途中を指す2つ目のpartを作り、`headers->last`をそのpartに設定していました。そのため、次の`ngx_list_push`は、その配列の末尾の1つ先に要素を書き込みました。これは、隣接するワーカーのプールのメモリを壊すヒープバッファオーバーフローで、ワーカープロセスが終了することがありました。また、名前の比較では、削除に指定した名前の長さの分だけを比べていました。そのため、保存されているヘッダの名前の接頭辞にあたる名前で削除すると、そのヘッダを削除しました。また、指定した名前より短い保存済みのキーでは、その末尾を越えて読みました。さらに、2つ目のpartがあるときに最初のpartが空になると、`headers->last`を動かさずに、次のpartを最初のpartの位置に移していました。その結果、その後に追加したヘッダは、リストから切り離されたpartに書き込まれ、読み戻せなくなっていました。
- 変更後：削除は、一致した要素を取り除くとき、ほかの要素を動かしません。そのため、nginxがこのリストの要素を指して保持しているポインタは、同じヘッダを指したままになります。このポインタは2種類です。1つは、nginxが専用のフィールドを持つヘッダの`ngx_table_elt_t *`で、`r->headers_in.user_agent`などがあります。もう1つは、同じ名前のヘッダをつなぐ`next`で、CookieやX-Forwarded-Forがその例です。また、`headers->nalloc`を、最後のpartの配列が現在の先頭から保持できる要素数以下に保ちます。この要素数には、使用中の要素も含みます。`ngx_list_push`は、partの要素の数が`nalloc`に達すると新しいpartを確保するので、最後のpartの配列の先へ書き込まなくなります。名前の比較では、バイト列の前に長さを比べます。そのため、保存されているヘッダの名前の接頭辞にあたる名前は一致しなくなり、指定した名前より短い保存済みのキーの末尾を越えて読むこともなくなります。空になったpartをリストから外すときと、次のpartを最初のpartの位置に移すときには、`headers->last`と`headers->nalloc`を、互いに合うように必ず更新します。
- 変更の理由：
  - 不具合：分割によって`headers->last`が満杯の配列の途中を指したので、次のpushがその配列の先に書き込みました。名前の比較は、保存されている名前の長さを見ていませんでした。次のpartを最初のpartの位置に移すときに、`headers->last`を動かしていませんでした。
  - 前の挙動を残せなかった理由：配列の範囲外への書き込みはメモリ安全性の問題で、ヒープを壊してワーカーを終了させることがあります。長い名前のヘッダを、その名前の接頭辞で削除するのは誤りです。最初のpartが空になった後に追加したヘッダは、失われていました。
  - ドキュメントが示していた挙動：[`Nginx::Headers_in#delete`](../class_and_method/README.md#nginxheaders_indeletestring)と[`Nginx::Headers_out#delete`](../class_and_method/README.md#nginxheaders_outdeletestring)は、deleteが指定した名前のヘッダを削除すると書いています。名前が指定した名前で始まるだけのヘッダを削除すること、リストのpartの範囲を越えて書き込むこと、後から追加したヘッダを失うことは、ドキュメントに書かれていません。
- 影響の範囲：mrubyのコードで、リクエストかレスポンスのヘッダを削除する設定です。オーバーフローの影響を受けるのは、ヘッダを削除したうえで、リストのpartを満杯にするだけのヘッダを持つリクエストに、さらにヘッダを追加する設定です。接頭辞の件で影響を受けるのは、別のヘッダの名前の接頭辞にあたる名前でヘッダを削除し、その両方のヘッダが削除されることを前提にしていた設定です。
- 必要な対応：オーバーフローと、追加したヘッダが失われる件については、対応は不要です。接頭辞の件については、ヘッダごとに正確な名前で削除してください。
- テスト：`test/t/cases/header_del.rb`のポート18105のテストです。

## ビルドとテストの変更

- `test/t/cases/var_setter_init.rb`は、`Nginx::Var`のセッターと`Nginx::Var#set`で`$args`に代入し、その値を読み戻します。設定は`test/conf/conf.d/72-var-setter-init.conf`のポート18104で、スクリプトは`test/html/var_setter_init.rb`です([GHSA-r7v5-479r-hmqr](https://github.com/matsumotory/ngx_mruby/security/advisories/GHSA-r7v5-479r-hmqr))。
- `test/t/cases/header_del.rb`は、リクエストのヘッダを削除します。設定は`test/conf/conf.d/73-header-del.conf`のポート18105で、スクリプトは`test/html/header_del.rb`です。試すのは次の5つの場合です。ヘッダの名前の接頭辞にあたる名前で削除する場合、2つ目のpartがあるときに満杯の最初のpartを空にする場合、満杯のpartの途中のヘッダを削除してからヘッダを追加する場合、partの途中のヘッダを削除する場合、先頭のヘッダを削除する場合です。後の2つは、削除した後も、`$http_user_agent`が読む`r->headers_in.user_agent`が同じヘッダを指したままであることを確かめます([GHSA-2gcp-h74q-c9g6](https://github.com/matsumotory/ngx_mruby/security/advisories/GHSA-2gcp-h74q-c9g6))。
