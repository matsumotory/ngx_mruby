# ngx_mruby v2.7.3

## アップグレードの前に読む挙動の変更

### 1. Nginx::SSL::ACME::Dehydrated#auto_cert_deployは、dehydratedの標準エラー出力も読み、CAの利用規約に同意します（#636）

- 変更前：auto-sslのmrbgemの`#auto_cert_deploy`は、dehydratedの標準出力だけを読んでいました。dehydratedの0.5.0以降は、CAの利用規約への同意を求める文を標準エラー出力に書くので、このメソッドはその文を見つけられず、`#auto_accept_terms`を呼びませんでした。まだ登録していないdehydratedのアカウントでは、dehydratedが止まって証明書が保存されず、ハンドシェイクが失敗しました。証明書が無いので、`Nginx::SSL#certificate_data=`が`TypeError`を発生させたためです。dehydratedが標準エラー出力に書いた文は、時刻とレベルの無い行のまま`error.log`に入っていました。
- 変更後：`#auto_cert_deploy`は、dehydratedの標準エラー出力を標準出力にまとめて（`2>&1`）実行します。同意を求める文を見つけると、`#auto_accept_terms`がアカウントを登録し（`dehydrated --register --accept-terms`）、`#auto_cert_deploy`がdehydratedをもう一度実行して、証明書を取得します。dehydratedが書いた文は、標準エラー出力の分も含めて、このメソッドが`Nginx::SSL.log`で書く`[info]`の行に入ります。
- 変更の理由：
  - 不具合：このプルリクエストが加えたauto-sslのmrbgemのテスト（`test/t/cases/auto_ssl.rb`）を、dehydrated 0.7.2とACMEのテストサーバーのPebbleで動かしたところ、新しいアカウントでは証明書を一度も取得できませんでした。このメソッドは、`test/conf/auto-ssl/dehydrated`にある版のdehydrated 0.4.0に合わせて書かれていました。0.4.0は、同意を求める文を標準出力に書いていました。
  - 前の挙動を残せなかった理由：このメソッドは、dehydratedが出力した文の中から同意を求める文を探します。標準エラー出力を別にしたままでは、ACME v2を話すどのdehydrated（0.6.0以降）でも、その文を見つけられません。Let's Encryptは、2021年にACME v1を止めてから、ACME v2だけを提供しています。
  - ドキュメントが示していた挙動：[docs/class_and_method/README.md](../class_and_method/README.md)は、APIについて`mrbgems/auto-ssl/mrblib`のスクリプトを参照するよう書いており、dehydratedの出力については何も書いていません。`#auto_accept_terms`と、`#auto_cert_deploy`の中の判定は、最初の実行で利用規約に同意するためにあります。
- 影響の範囲：`test/conf/auto-ssl/nginx.conf.dehydrated_example`のように、`Nginx::SSL::ACME::Dehydrated#auto_cert_deploy`を呼ぶTLSのハンドシェイクのハンドラです。`error_log`のレベルが`info`より上のとき（例の設定は`notice`です）、dehydratedが標準エラー出力に書く文は、エラーも含めて、`error.log`に出なくなります。
- 必要な対応：新しいアカウントで証明書を取得するための対応は要りません。dehydratedのエラーを`error.log`で見るには、そのサーバーが使う`error_log`のレベルを`info`にしてください。

## ビルドとテストの変更

- Redis、ACMEのテストサーバーのPebble、dehydratedを使うauto-sslのmrbgemのテストを加えました。`test/t/cases/auto_ssl.rb`は、`sh test/auto_ssl/deps.sh start DIR`が準備したディレクトリを`NGX_MRUBY_TEST_AUTO_SSL`が指すときに動き、CIは`build`のマトリクスのすべてのセルでこのテストを動かします。このテストは、テストのnginxの新しいポートの18171と18172と、このテストが起動する2つ目のnginxの18173と18174を使います。サービスは、6379、8053、8055、14000、15000で待ち受けます。詳しくは、[docs/test/README.md](../test/README.md)の「Testing the auto-ssl mrbgem」に書いてあります（[#636](https://github.com/matsumotory/ngx_mruby/pull/636)）。

## アップグレード

サポートするnginxのバージョンは、[README.md](../../README.md)に書いたとおり、nginxのmainlineとstableの系列です。CIは、nginx 1.31.6、1.30.5、1.28.3、1.26.3をビルドします。

- 追加、改名、削除したディレクティブはありません。このリリースで、モジュールをビルドし直してください。2.7.2をビルドしたときと同じ方法でビルドし、いつもどおりバイナリか動的モジュールを置き換えてください。

アップグレードの前に、次の点を確かめてください。各行は、上の各項目の「必要な対応」です。

- `Nginx::SSL::ACME::Dehydrated#auto_cert_deploy`：新しいアカウントで証明書を取得するための対応は要りません。dehydratedのエラーを`error.log`で見るには、そのサーバーが使う`error_log`のレベルを`info`にしてください（項目1）。
