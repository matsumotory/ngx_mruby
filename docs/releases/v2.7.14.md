## Build and test changes

- CI: the required check `ci-ok` of `test.yml` needs the `perf` job, so a `FAIL` or `ERROR` row of the performance comparison fails it, and a `WARN` row does not. `test/perf/accepted.txt` lists the accepted differences of the comparison, with two conditions. A `mruby-version` line applies when the bundled mruby of the base and of the head match its versions; the file has no such line on `master`. A `pull-request` line names the base branch and the number of a pull request (for example `pull-request master 812 auth 7`) and applies only in the `perf` job of that pull request, which passes both to `perf.rb` in `PERF_BASE_REF` and `PERF_PULL_REQUEST`. A pull request adds such a line after the owner has accepted its `FAIL` in a comment, and the run passes. The comparison judges the Ir per request without the GC, as before ("Known differences" and "In CI" under "Performance comparison with callgrind" in [docs/test/README.md](../test/README.md)) (#PR)
