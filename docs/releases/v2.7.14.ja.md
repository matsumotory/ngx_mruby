# ngx_mruby v2.7.14

## 更新前に確認する挙動の変更

### Nginx::Headers_outで設定したContent-Lengthを、応答のヘッダ行として送らなくなりました

- 変更前：`Nginx::Headers_out#[]=`のキーに`Content-Length`を指定すると、nginxが応答の本文の長さをもとに出力する`Content-Length`とは別に、もう1つの`Content-Length`の行が応答に追加されていました。そのため、値の異なる2つの`Content-Length`の行を持つ応答になることがありました。
- 変更後：`Nginx::Headers_out`で設定した`Content-Length`は送られなくなりました。スクリプトが設定しないときと同じく、nginx自身が応答の`Content-Length`を出力します。
- 変更の理由：
  - 不具合：`Nginx::Headers_out`で設定した`Content-Length`が、nginxが出力する行とは別に、2つ目の`Content-Length`の行として追加されていました。値の違う2つの`Content-Length`の行を持つ応答は、本文の長さが1つに定まりません。nginxが`Transfer-Encoding: chunked`で送る応答では、スクリプトの行が`Transfer-Encoding`と並んで追加され、この場合も本文の長さが1つに定まりませんでした。詳細は[GHSA-2cf7-qh69-j29q](https://github.com/matsumotory/ngx_mruby/security/advisories/GHSA-2cf7-qh69-j29q)にあります。
  - 前の挙動を残せなかった理由：スクリプトが設定した行を、どの場合でも本文と一致させることはできないため、nginxが本文を区切るのに使う長さだけを送ります。
  - ドキュメントが示していた挙動：2.x系の`docs/class_and_method/`は、`Nginx::Headers_out`で`Content-Length`を設定する動作を説明していませんでした。
- 影響の範囲：content handler、フェーズのハンドラ、output header filterのいずれかで、Rubyのコードが`Nginx::Headers_out`を通じて`Content-Length`を設定している構成。`Nginx::Headers_out#[]`による`Content-Length`の読み取りと、`#delete`による削除は変わりません。
- 必要な対応：スクリプトから、`Content-Length`への`Nginx::Headers_out#[]=`による代入を削除してください。nginxが応答の長さを出力します。固定長の応答を返すには、その長さのバイト列を`Nginx.rputs`で出力すれば、その合計をnginxが`Content-Length`として送ります。

## ビルドとテストの変更

- CI：`test.yml`の必須のチェック`ci-ok`が`perf`ジョブを必要とします。性能の比較に`FAIL`か`ERROR`の行があると`ci-ok`は失敗し、`WARN`の行では失敗しません。`test/perf/accepted.txt`には、比較で受け入れた差を書きます。条件は2つです。`mruby-version`の行は、ベースとヘッドが同梱するmrubyのバージョンが、行に書いたバージョンと一致するときに当てはまります。`master`のファイルには、この行はありません。`pull-request`の行には、プルリクエストのベースブランチと番号を書きます。たとえば`pull-request master 812 auth 7`です。行が当てはまるのは、そのプルリクエストの`perf`ジョブだけです。ジョブは、ベースブランチと番号を`PERF_BASE_REF`と`PERF_PULL_REQUEST`で`perf.rb`に渡します。オーナーがプルリクエストのコメントで`FAIL`を受け入れた後に、そのプルリクエストがこの行を加えると、実行は成功します。比較は、これまでどおり、GCを除いたリクエストあたりのIrで判定します。説明は、[docs/test/README.md](../test/README.md)の「Performance comparison with callgrind」の「Known differences」と「In CI」にあります(#865)。

## アップグレード

- ディレクティブの追加、名前の変更、削除はありません。2.7.13と同じ方法でこのリリースのモジュールをビルドし、バイナリか動的モジュールをいつもどおり置き換えてください。`Nginx.module_version`は`2.7.14`を返します。
- スクリプトが`Nginx::Headers_out`で`Content-Length`を設定している場合は、その`[]=`を外してください。nginxが応答の長さを送ります。固定の長さの応答は、その長さのバイトを`Nginx.rputs`で書きます。

アップグレードの前に、上の「更新前に確認する挙動の変更」を読んでください。
