# ngx_mruby v2.7.7

## 更新前に確認する挙動の変更

### クラスが`inspect`か`backtrace`を再定義している例外の、`error.log`の行(#803)

- 変更前：Rubyのコードが出した例外のクラスが`inspect`をRubyで再定義していると、再定義したメソッドが何をしても、ngx_mrubyはその例外の行を`error.log`に書きませんでした。ngx_mrubyは、例外がmrubyの状態に残ったままこのメソッドを呼んでいました。同梱のmrubyは、この状態で呼ばれたメソッドの結果の代わりに、残っている例外を返します。そのため、結果がStringになることはありませんでした。`--with-debug`のビルドでは、再定義した`backtrace`も同じ例外を返し、ngx_mrubyはdebugのレベルで`backtrace must be Array. mrb_type=18`を書き、フレームを書きませんでした。`mruby_set`のハンドラから`Nginx.redirect`で移ったlocationのcontentハンドラで、このような`inspect`か`backtrace`が例外を出すと、その例外は`mruby_set`のハンドラまで伝わり、nginxはリクエストを終えませんでした。クライアントは、待つのをあきらめるまで応答を待ちました。
- 変更後：ngx_mrubyは、残っている例外を退避してから`inspect`と`backtrace`を呼び、これらのメソッドが出した例外をログの処理の中で止めます。`inspect`がStringを返すと、行にはそのStringが入ります。これは、`inspect`を再定義していないクラスの例外と同じ扱いです。`inspect`が例外を出すと、行には`#<Class> (inspect raised Class)`が入ります。前の`Class`は例外のクラス、後の`Class`は`inspect`が出した例外のクラスです。`inspect`がString以外を返すと、行には`#<Class> (inspect did not return a String)`が入ります。`--with-debug`のビルドでは、再定義した`backtrace`の結果のうちStringの要素を1行ずつ書き、それ以外の要素は飛ばします。例外を出すか、Arrayを返さない`backtrace`は、これまでどおりdebugのレベルで書きます。別のmrubyの呼び出しの中でも、リクエストは500で終わり、セッションは中断されて終わります。workerは次のリクエストに進みます。
- 変更の理由：
  - 不具合：`inspect`と`backtrace`は、例外が残ったまま呼ばれていました。そのため、再定義したメソッドは結果を返せず、メソッドが出した例外もログの処理の中で止まりませんでした。別のmrubyの呼び出しの中では、この例外のためにリクエストが終わりませんでした。`next`では、同じ呼び出しを#796と#799で直しています。このプルリクエストは、その直しを2.xに入れます。
  - 前の挙動を残せなかった理由：ログの処理からリクエストのnginxの関数を越えて伝わった例外は、リクエストとその接続を開いたままにします。行を書かない例外は、運用者からエラーを隠します。Stringを返せない`inspect`の代わりにクラス名を書く行は、3.xが同じ例外に書く行と同じです。これで、2.xと3.xは同じ行を書きます。
  - ドキュメントが示していた挙動：ドキュメントは、クラスが`inspect`か`backtrace`を再定義している例外について、何も書いていませんでした。
- 影響の範囲：`inspect`か`backtrace`をRubyで再定義したクラスの例外を出す、すべての種類のハンドラのスクリプトです。HTTPとstreamのハンドラに加えて、nginxが設定を読むときと、workerの開始と終了のときに動くコードも含みます。これらを再定義していないクラスの例外は、これまでと1バイトも変わらない行になります。
- 必要な対応：ありません。ただし、このような例外の行を`error.log`から読み取っている場合は、その行が書かれるようになり、再定義した`inspect`のテキストかクラス名が入ることに注意してください。

## 新機能

ありません。

## 不具合の修正

- 例外のクラスが`inspect`か`backtrace`を再定義していて、`mruby_set`のハンドラから`Nginx.redirect`で移ったlocationのcontentハンドラでそのメソッドが例外を出したとき、nginxはリクエストを500で終えるようになりました。これまでは、例外が`mruby_set`のハンドラまで伝わり、クライアントは待つのをあきらめるまで応答を待っていました(#803)。
- `--with-debug`のビルドで、再定義した`backtrace`の結果のうちString以外の要素を飛ばすようになりました。これまでは、すべての要素をStringとして読んでいました(#803)。

## ビルドとテストの変更

- 新しいテストのケースとして、`test/t/cases/exception_log_script_methods.rb`と、ポート18091の`test/conf/conf.d/94-exception-log-script-methods.conf`のサーバー、ポート12383と12389の`test/conf/conf.d/stream/52-exception-log-script-methods.conf`のstreamのサーバーを加えました(#803)。

## アップグレード

- ディレクティブの追加、名前の変更、削除はありません。2.7.6と同じ方法でこのリリースのモジュールをビルドし、バイナリか動的モジュールを置き換えてください。

アップグレードの前に、次の点を確かめてください。各行は、項目の「必要な対応」です。

- `inspect`か`backtrace`を再定義したクラスの例外の行を`error.log`から読み取っているツール：このような例外の行が書かれるようになり、再定義した`inspect`のテキストかクラス名が入ります。
