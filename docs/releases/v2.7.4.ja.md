## ビルドとテストの変更

- CI：コードかテストを変えるreadyのプルリクエストは、`test.yml`の`build`のマトリクスのうち、4つのセルを流し、全部のセルは流しません。全部のセルは、nginxのバージョン、リンクの形、`--with-openssl-src`の有無の16の組み合わせと、sanitizerのセルです。4つのセルは、`--with-openssl-src`を付けたnginx 1.31.8の静的モジュール、nginx 1.30.6の動的モジュール、sanitizerのセル、valgrindの下のセルです。sanitizerのセルとvalgrindの下のセルは、nginx 1.31.8の静的モジュールをビルドします。sanitizerのセルは、AddressSanitizerとUndefinedBehaviorSanitizerを付けてビルドします。全部のセルを流すのは、valgrindの下の夜間の実行、タグのpush、新しいラベル`full-matrix`を付けたプルリクエスト、入力`base`を付けないか入力`valgrind`を付けた「Run workflow」です。タグの前の点検のプルリクエストは、このラベルを付けます。`v*.x`のブランチへのpushは、`master`と`next`へのpushと同じく、ビルドを流しません。`test/ci/changes.sh`は、`next`と再び同じスクリプトになり、実行の種類をオプション(`--label`、`--draft`、`--push`、`--tag`、`--dispatch`、`--valgrind`)で受け取り、`build`を`standard`、`full`、`none`のどれかで出します。説明は、[docs/test/README.md](../test/README.md)の「Which jobs a run starts」にあります(#704)。
