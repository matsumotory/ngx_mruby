# セキュリティポリシー

## サポートする<wbr>バージョン

| バージョン | 場所 | 状態 |
|---|---|---|
| 2.xの最新のリリース | v3.0.0でv3を`master`へ昇格するまでの`master`、`v2.x`、最新の`v2.*`のタグ | v3.0.0の後12か月までサポートします |
| v3のプレリリースの`v3.0.0-alpha.N`、`-beta.N`、`-rc.N` | `next` | できる範囲で対応します |
| 2.xの古いリリースと1.x | 古い`v2.*`のタグと`v1.*`のタグ | サポートしません。2.xの最新のリリースへアップグレードしてください |

2.xのセキュリティの修正は、2.xの新しいパッチリリースとしてリリースします。v3の計画で決めたとおり、v3.0.0をリリースした後12か月の間、2.xをサポートします。この決定は、`next`にある[docs/proposals/v3-plan.md](https://github.com/matsumotory/ngx_mruby/blob/next/docs/proposals/v3-plan.md)の7節、項目11にあります。v3.0.0をリリースしたら、サポートが終わる日をこのページとREADMEに加え、このテーブルに3.xを加えます。どのブランチにどの系列があるかは、[Branch strategy](../../../README.md#branch-strategy)にあります。

## 対象の<wbr>範囲

ngx_mrubyは、nginxの設定と、設定で読み込むRubyのコードを信頼します。クライアントが送るものは、信頼しない入力として扱います。ディレクティブとメソッドをドキュメントのとおりに使う設定で、ngx_mrubyの不具合のために次のことが起きる場合は、対象の範囲に入ります。ngx_mrubyがバッファの外のメモリを読むか書く場合、ワーカーが終了するかハングする場合、別のリクエストのデータが漏れるか変わる場合です。クライアントが制御する入力でその不具合が起きる場合は、特に対象に入ります。運用者のコードが、書いたとおりに動いた結果は、対象に入りません。たとえば、クライアントの入力を`eval`、シェルのコマンド、ファイルのパスに渡すスクリプトです。運用者が信頼しない相手から設定やRubyのコードを受け取る構成も、対象に入りません。境界の両側と対象の範囲の全体は、[信頼境界](../../security/trust-boundary.md)にあります。不具合が対象に入るか分からないときは、非公開で報告してください。

## 脆弱性を<wbr>報告する

セキュリティの脆弱性は、GitHubの公開のissue、プルリクエスト、ディスカッションで報告**しないでください**。

脆弱性は、GitHubのprivate vulnerability reportingで、非公開で報告してください。リポジトリの**Security**のタブを開き、**Report a vulnerability**をクリックします。報告のフォームは<https://github.com/matsumotory/ngx_mruby/security/advisories/new>にあります。

そのフォームを使えないときは、非公開の連絡手段だけを尋ねる公開のissueを開いてください。そのissueには、問題の詳細を何も書かないでください。

## 報告に<wbr>書くこと

- ngx_mrubyのバージョンかコミット、nginxのバージョンとconfigureのオプション、OpenSSLのバージョン、`build_config.rb`に加えた変更
- 最小の`nginx.conf`と、関係するRubyのコード
- 再現する手順、期待した挙動、実際の挙動
- あなたが理解している影響と、攻撃者に必要な条件。影響の例は、クラッシュ、メモリの内容の漏えい、サービス拒否です
- バックトレース、sanitizerの出力、valgrindの出力
- この問題をほかの人がすでに知っているかどうかと、報告者のクレジットをどう載せてほしいか

## 報告の<wbr>後の<wbr>流れ

ngx_mrubyはボランティアが保守しているので、返答までの時間は保証できません。私たちは、報告を受け取ったことを伝え、アドバイザリで進み具合を知らせます。詳しい情報を尋ねることもあります。2週間たっても返事が無いときは、同じアドバイザリに催促を書き込んでください。

## 協調した<wbr>脆弱性の<wbr>開示

- 修正は、アドバイザリの一時的な非公開のフォークで用意し、新しいバージョンとしてリリースします。
- 修正したリリースが出たときに、アドバイザリを公開します。適切な場合は、CVEも付けます。報告者が望まない場合を除き、報告者をクレジットに載せます。
- アドバイザリを公開するまで、または私たちとあなたが公開の日に合意するまで、問題を秘密にしてください。

同梱のコンポーネントやサードパーティのコンポーネントの脆弱性は、それぞれのupstreamのプロジェクトにも報告してください。そのコンポーネントは、mruby、nginx、ngx_devel_kit、mrbgemsです。その問題がngx_mrubyのビルドに影響するときは、私たちにも知らせてください。
